# Changelog

## Unreleased

- BREAKING CHANGE: runtime crates are renamed to standard Bitcoin domain names: `bitcoin-rs-execution` (`crates/execution`) → `bitcoin-rs-chain` (`crates/chain`, import `bitcoin_rs_chain`), `bitcoin-rs-projection` (`crates/projection`) → `bitcoin-rs-index` (`crates/index`, import `bitcoin_rs_index`), `bitcoin-rs-serving` (`crates/serving`) → `bitcoin-rs-rpc` (`crates/rpc`, import `bitcoin_rs_rpc`), and `bitcoin-rs-wire` (`crates/wire`) → `bitcoin-rs-p2p` (`crates/p2p`, import `bitcoin_rs_p2p`). Downstream Cargo dependencies, feature flags, and Rust import paths must be updated to the new crate names.

- BREAKING CHANGE: runtime `fjall` and `redb` backends and the `rocksdb` feature switch are removed. RocksDB is the mandatory, unconditionally compiled default; existing Fjall/Redb datadirs require offline conversion with `bitcoin-rs-storage-convert`, not an in-place reset.
- BREAKING CHANGE: workspace crates are consolidated into the canonical `bitcoin-rs-consensus`, `bitcoin-rs-storage`, `bitcoin-rs-chain`, `bitcoin-rs-index`, `bitcoin-rs-p2p`, `bitcoin-rs-mempool`, `bitcoin-rs-rpc`, and `bitcoin-rs-node` owners (named after the rename above). Downstream dependencies and public type imports must use their owning crates; `BlockHeader` and `ChainWork` are available from `bitcoin_rs_consensus::header_rules`, not `bitcoin_rs_chain::chain::node`.
- BREAKING CHANGE: storage `CreatedOutput::script` and `SpentPrevout::script` use immutable full-buffer `FactsScript` instead of arbitrary `Bytes`. Downstream constructors and consumers must use `FactsScript`; full-buffer ownership makes retained capacity and sharing accountable.
- Maintenance settles completed disconnect publication debt on its existing checkpoint cadence, including rollbacks to the same or a lower height. Stable-read acquisition counts include successful blocking, immediate and timed locks, and verification preserves typed corrupt-frame evidence.
- BREAKING CHANGE: `RetryReason` gains `MissingAppliedTip` and `PendingCapabilityCoverage(IndexCapability)`, and `TipMoved` renames its fields to `expected_revision` and `current_revision`. A downstream exhaustive match must change.
- BREAKING CHANGE: `AppliedEpoch::commit_id` is renamed to `runtime_revision`. It counts runtime wake changes, not durable chain commits.
- BREAKING CHANGE: `NodeBudget::available_of_charges` is renamed to `charged_bytes`. It returns the bytes charged to an owner, not the bytes still available.
- A rejected snapshot ingest on a fresh node clears the activation marker it wrote. If the marker cannot be cleared, the chain closes for recovery and the call reports `PartialIngestNotDiscarded`.
- Startup treats any in-flight snapshot activation marker as a cold start with no engine image, including when a published checkpoint exists below the marker base.
- BREAKING CHANGE: `RecoveryError::SnapshotBaseCheckpointMissing` reports a pinned snapshot base without a compatible checkpoint. `PinnedCheckpointMismatch` is limited to a checkpoint that disagrees with the pin.
- Recovery and converter checks of a snapshot-base checkpoint stream the engine coin rows into the pinned commitment. They no longer build a resident `UtxoSet`.
- Window prevout charges are admitted from a size preflight before the prevout vectors are built. A refused admission builds no vectors and holds no charge.
- A window that continues into a tail window after a duplicate transaction now releases its prevout charge before the tail starts, so the tail window keeps its batched script proof under a tight budget.
- Window workspace sizing tracks each staged coin record incrementally instead of re-encoding it. Flush admission adds the retained working-set bytes to the encoded size.
- Manifest import and startup attachment resolve relative paths under the data directory and use the same bounded manifest reader.
- Streamed coin commitments reject rows whose key length or transaction ID differs from the encoded coin record.
- Checkpoint restore copies recorded engine files into a newly claimed scratch directory. It leaves pre-existing directories and published file bytes unchanged.
- Checkpoint manifests reject colons in engine-image path components, including drive-relative paths and alternate data-stream names.
- Filling an already resident coin-cache key leaves its cached bytes and ledger charge unchanged, even when the shared budget is full.
- Index resets remove abandoned shared recovery logs when the last published owner resets, including after an interrupted reset. Recovery history remains intact for published sibling indexes.
- Spender queries retain confirmed spends after independent transaction-lookup and script-history artifact imports. New spend rows resolve the funding transaction through the script-history directory before falling back to transaction lookup.
- Projection spill sorting charges retained payload capacities and row-vector backing storage. Spill, finish, and drop free row storage before returning its budget charge; a failed spill keeps its retained rows charged.
- A filter catch-up that seals a shared transaction tail preserves publication for every existing capability whose rows move. Seal recovery uses the same owners, and unrelated capability watermarks do not advance.
- BREAKING CHANGE: `DerivedIndexQuery::transaction_height` is replaced by `transaction_block`, which returns the transaction body with its captured occurrence height and block hash. Esplora confirmation metadata uses that block identity across reorgs, including ABA publication changes.
- Confirmed transaction Merkle proofs load the block body by the occurrence block hash captured with the transaction metadata, not by a later active block at the same height.
- Esplora transaction pages for a block that is no longer on the applied chain capture one applied view, resolve every confirmation, and return the retry refusal when any applied tip was published meanwhile, including a tip that returned to the starting block. They no longer mix confirmations from two applied branches in one page. Transactions of that block that were mined again at different heights keep their own confirmations.
- Projection enforces serving-view expiry at read completion and between emitted compact-filter records.
- Network ingress leaves the existing foreground reserve available within the staged-image allowance. Its capacity and atomic admission check use the reduced ceiling; execution retains the full owner cap. The node-wide total, cache shares, and resource-refusal classification are unchanged.
- Epoch-5 conversion converts retained ordinary and historical checkpoint engine images to the requested backend and schema-6 undo format. Epoch-5 and current-epoch backend copies preserve the root `full-revalidation` marker.
- Projection preserves blockwise ScriptLive rollback when sealed historical generations retire. Compact-filter attachment and restart preserve transaction ordinals. Same-height capability backfill merges undo logs and retains the original rollback frontier.
- Epoch-4, epoch-5, and current-epoch backend conversion preserve production historical memory-engine checkpoints. Legacy memory undo rows are converted to schema 6. Conversion validates the image through the existing loader and rejects mixed engine files without publishing a schema marker.
- Coin statistics retain unchanged outputs during partial spends. The committed feed emits only removed, inserted, or changed coins, including height and coinbase changes; final-record precedence and the existing point-read path are unchanged.
- Production chainstate readers no longer expose writable coin-store or commit-authority handles. The retained fixture accessors require the existing test seam.
- Snapshot serialization derives a reader-owned view's MuHash trailer from the captured coins, not from a later live listener or a zero fallback.
- Production UTXO readers no longer expose writable coin stores or mutable backing sets. Whole-set query images belong to their captured views and are released when those views drop. Transaction confirmation-height lookup uses the typed reader query.
- Recreated outpoints remain readable after earlier incarnations are spent.
- Window coin effects use ordered vout indexes instead of repeated output-vector scans.
- Execution preserves valid committed prefixes when later window header admission fails.
- Epoch-3 equal-head conversion streams authenticated checkpoint artifacts into synced atomic target files. Valid canonical header artifacts larger than 64 MiB no longer fail an extra whole-file publication limit.
- The chainstate cache allowance is split equally between the storage engine and `CoinStore`, after the unchanged txindex reservation. The engine receives half, floored to whole bytes. Coins receive the remainder, including any odd byte. The node ledger uses these shares as the engine and coin owner caps. The dbcache total and clamp, other owner budgets, foreground reserve, and startup log fields are unchanged. MDBX's unused engine share is not reassigned to coins.
- Script-history reads include sealed generations whose transaction ordinals start above zero.
- Script activity counts each confirmed transaction once when it has several outputs or both funding and spending occurrences for the same script. Funding results still retain each distinct output.
- Retiring one sealed index capability preserves transaction and spender directories while another published capability still needs them. Retiring the last owner reclaims those rows.
- Synchronization stops when a follower refuses settlement after a durable window commit. The committed block count stays intact, admission remains fenced, and the node requires recovery instead of retrying committed blocks.
- Snapshot seed staging keeps the published ScriptLive base available. Aborting a staged seed preserves that base, and a completed replacement becomes visible only when the worker publishes it.
- Bulk index rebuilds resolve each spend to the latest earlier creation when the same transaction ID occurs more than once in the rebuild range.
- Dependency refresh: `parking_lot` moves to the `0.13` line, and `proptest`/`proptest-state-machine` move to `1.12`/`0.9`. `crates/node/src/metrics/tests.rs` replaces the removed `const_mutex(())` constructor with `Mutex::new(())`, which is const in `lock_api 0.5`. Transitive crates still pin `parking_lot 0.12`, and `proptest 1.12` pulls the `rand_core 0.10` family beside the existing `0.9.5`; both are exact-version duplicate splits documented in `docs/contracts/dependency-range.md`. No runtime behavior change is claimed.
- Independent workspace lock graphs (`fuzz`, `tools/ldk`, `tools/swiftsync-poc`, `tools/stratum-sv2/template-provider`) are resynchronized to the refreshed dependency families: `sha3` 0.12, `arc-swap` 1.9.5, and the `bitcoin_hashes` 1.2 / `secp256k1` 0.33.1 coexistence already adopted by the root graph. `surrealkv` is absent from all four graphs and was not added. No manifest or source changes were required.
- Upgrade the Stratum V2 dependency family to binary 8.0.0, framing 9.0.0, codec 8.1.0, Noise 2.1.0, mining 13.0.0, and common messages 10.0.0. Update the mining server and clients for the new decoder and message fields. Remove legacy AES-family duplicate allowances: the resolved graph now has one version each of `aes`, `aes-gcm`, `ctr`, `ghash`, and `polyval`.
- Upgrade direct `bitcoin_hashes` to 1.2.0; hash algorithms and byte encodings are unchanged. Bitcoin 0.32.102 remains the reference dependency on its own exact hash dependency line.
- Upgrade direct `secp256k1` to 0.33.1, adapting context-free key operations, owned ECDSA messages and raw Schnorr message bytes. Bitcoin 0.32.102 and the SV2 authority-key dependency keep their existing separate versions; signature rules and storage encodings are unchanged.
- Streaming index artifact restore (`crates/index/src/portable/restore.rs`, `segment/spill.rs`, `segment/import.rs`, `index/write.rs`). `TxLookup` and `ScriptHistory` artifacts now attach through one bounded streaming re-encode: the verified artifact decodes into spill runs on scratch, the merge orders rows, and one segment attach seals them. The re-encode holds no more than 64 MiB of decoded rows in memory at once. The portable attach functions take the spill budget as a new argument.
- BREAKING CHANGE: `attach_tx_lookup_artifact`, `attach_script_history_artifact`, and `attach_compact_filter_artifact` take a `&SpillBudget` argument; the `TxIndexWriter` attach methods for `TxLookup` and `ScriptHistory` take streamed run families instead of `ImportedSegment`.
- BREAKING CHANGE: `MempoolGateway::remove_for_block`, `settle_block_facts`, `expire`, `clear` and `evict_below_fee_rate` return `Result` carrying `MempoolError::DeliveryQueueFull` when a reentrant observer callback commits past the bounded delivery queue; callers propagate the error.
- Coins live in the engine `coins` keyspace. Windows and blocks commit their coin replacements in the same atomic batch as the durable head, undo rows and body index. The resident `UtxoSet` is the snapshot reader only.
- Epoch 4 datadir format. The `3 -> 4` step of `bitcoin-rs-storage-convert` loads the coin image of the newest checkpoint into the engine, replays the suffix to the durable head, and carries the epoch-3 `assumeutxo-historical-checkpoints` generations with their engine coins. Epoch-4 coin records use the Core-compressed txout value framing.
- The chainstate journal and its replay are removed, and so is the `utxo-v4.dat` checkpoint coin image as an authority. New checkpoints carry an engine image; `chainstate-checkpoints/` generations from epoch 3 are not copied into the epoch-4 datadir. The `[chainstate_journal]` config table and `BITCOIN_RS_CHAINSTATE_JOURNAL*` variables are removed.
- BREAKING CHANGE: the `[chainstate_journal]` table and `BITCOIN_RS_CHAINSTATE_JOURNAL*` variables are removed. A TOML config that sets the table fails startup as an unknown key; the removed environment variables are ignored.
- The `3 -> 4` step carries the epoch-3 full-revalidation marker (`chainstate-journal/full-revalidation`) to the epoch-4 datadir root, so a datadir marked for full revalidation still revalidates from cold after conversion.
- Derived index writes (`crates/index/src/index/block.rs`, `write.rs`, `rows.rs`). The gap fallback parses each block body once, where it parsed twice before; the committed-facts path parses nothing. Legacy `TxConfirmed`, `Funding`, `Spending`, and compact-filter key rows are no longer written; transaction, script-history, and filter data live in the segment tail. Index format marker is 9: every per-block tail log record now carries the block hash anchor, so existing derived indexes rebuild on start.
- BREAKING CHANGE: the index format marker moves to 9. `IndexWriter::open` refuses an index at an older marker, then startup resets the index and rebuilds it.
- Batch byte limit (`crates/index/src/index/prepared.rs`, `tail_writes.rs`, `rows.rs`, `write.rs`). A prepared batch's planned bytes now bound every index write its commit makes: they count the segment-tail undo log (`tail_log` family on `index.family_planned_write_bytes`), every spend row the tail can emit, and the per-commit watermark, revision, generation-descriptor, and consumer-cursor writes. The cursor is charged at its worst case, a full `CURSOR_BYTE_LEN` value, whatever the caller sets. Batches admitted under the old figure can carry more bytes than their limit; the same limit now admits fewer blocks per batch.
- Verified snapshot state for AssumeUTXO import (`crates/storage/src/utxo/core_snapshot.rs`, `crates/chain/src/assumeutxo.rs`, `crates/node/src/snapshot.rs`). `read_verified` seals the decoded portable set with its base hash, height, commitment and coin statistics. Portable activation streams coins into the engine and checks their commitment against the pinned hash. Before publishing the snapshot-base checkpoint, its persist closure rescans the installed engine coins with `CoinStore::commitment(pinned.height, None)` to check the pinned hash again and derive coin statistics. Caller digests and snapshot trailers still establish no trust. Recorded compatibility boundary: files repeating txid groups are refused (`TransactionOrder`, RPC `-22`); Core 31.1 accepts such a file. No performance gain is claimed.
- The native v4 UTXO snapshot bootstrap path is removed (`Node::activate_assumeutxo_snapshot_file`, `NodeState::activate_assumeutxo_snapshot_file`, `SnapshotControl::import_native`, `AssumeUtxoManager::activate_native_snapshot`). Snapshot activation accepts Core portable v2 via `loadtxoutset` and manifest bundles via `Node::import_manifest`.
- BREAKING CHANGE: `Node::activate_assumeutxo_snapshot_file` is removed; embedders activate snapshots via `Node::import_manifest` (Core v2); native v4 snapshot files are no longer accepted as bootstrap input.
- Snapshot activation publishes a checkpoint at the snapshot base before the durable-head commit, and restart resumes from that checkpoint. The `assumeutxo/<base>/coins.dat` and `headers.dat` archive, its writer and reader (`write_coins_archive`, `write_headers`, `load_verified`), and the reservation probe are removed. Activation scans the installed engine coins and refuses a `hash_serialized` that differs from the pinned commitment.
- BREAKING CHANGE: the snapshot archive is gone and older datadirs need the converter. Epoch 5 introduced the snapshot-base checkpoint requirement for restart in place of the archive. The current datadir format is epoch 6; the current binary refuses epoch 4 and epoch 5 datadirs. Convert directly with the `4 -> 6` step of `bitcoin-rs-storage-convert`, which verifies a valid archive (`headers.dat` linkage and proof of work, `coins.dat` hash against the compiled pinned value) and publishes the checkpoint into the new datadir without copying the archive. A datadir with a compatible checkpoint converts without republication, and an archive that fails verification refuses conversion with no marker written.
- `loadtxoutset` RPC always decodes the input as a Core portable v2 snapshot, independent of the filename; a `.json` suffix no longer routes a real Core file into the manifest decoder, and manifest bundles keep activating only through `Node::import_manifest`.
- Epoch 6 datadir format (`crates/storage/src/utxo/undo_codec.rs`, `tools/storage-convert`). An undo record holds only the coins that its block spends (`UNDO_FORMAT_VERSION = 2`), and the node derives the created outputs from the block bytes on disconnect. The `5 -> 6` step of `bitcoin-rs-storage-convert` recodes each version 1 undo row. Epoch 3 and epoch 4 sources chain their steps with that recode and write marker `6`.
- BREAKING CHANGE: a datadir at schema 5 or older is refused until `bitcoin-rs-storage-convert` writes it to schema 6.
- `UtxoReader::get`, `get_entry` and `has_live_outputs_for_txid` return `UtxoError` when the coin store cannot read or decode a coin row, and no longer report that coin as absent. `gettxout` and `gettxoutproof` answer Core `-32603`, `/rest/getutxos` answers HTTP 500, compressed-transaction decompression answers `coin set could not be read; retry` while compression reports the prevout as unreadable in its warnings, `generateblock` with raw transactions fails, and the mempool admission view returns no snapshot. Each of these previously answered as if the coin did not exist.
- BREAKING CHANGE: `UtxoReader::with_stable_view`, `lock_stable_view` and `fixture_with_set` return `Result`. Fixture constructors require `test-seam`. Stable views report read failures, and indexed point queries avoid a full coin scan. CoinStats uses each coin key's final image and applies each committed feed under one lock.
- The `3 -> 4` converter validates canonical checkpoint artifacts and historical references, and bounds recovery-marker reads.
- The `4 -> 6` and `6 -> 6` backend conversions also convert ordinary and historical checkpoint engine images, preserve their metadata, and verify each image's row counts and digests.
- Memory-engine checkpoint publication syncs the checkpoint file and its directory. It releases the coin-map read lock before file I/O, after it has copied a consistent checkpoint image.
- Genesis-and-child bootstrap accounts for the valid committed prefix, and recovery streams engine coins instead of collecting the full coin image.
- Offline import reports a stable UTXO view rebuild failure separately from a CoinStats scan failure and preserves the underlying error.
- Workspace `sha3` dependency upgraded from `>=0.11, <0.12` to `>=0.12, <0.13`; `default-features = false` is preserved and no source changes were required. The Tor v3 onion address checksum encoding is unchanged.
- Upgrade direct `base64` to `>=0.23.1, <0.24` with `std` and without its new default `simd-unsafe` feature. Existing encodings and decoder configurations are unchanged.
- The workspace locks `arc-swap` to version 1.9.5.
- The workspace locks `surrealkv` to version 1.4.0. Its manifest write-path change keeps the existing storage format.
