# Changelog

## Unreleased

- Script-history reads include sealed generations whose transaction ordinals start above zero.
- Script activity counts each confirmed transaction once when it has several outputs or both funding and spending occurrences for the same script. Funding results still retain each distinct output.
- Retiring one sealed index capability preserves transaction and spender directories while another published capability still needs them. Retiring the last owner reclaims those rows.
- Synchronization stops when a follower refuses settlement after a durable window commit. The committed block count stays intact, admission remains fenced, and the node requires recovery instead of retrying committed blocks.
- Streaming index artifact restore (`crates/projection/src/portable/restore.rs`, `segment/spill.rs`, `segment/import.rs`, `index/write.rs`). `TxLookup` and `ScriptHistory` artifacts now attach through one bounded streaming re-encode: the verified artifact decodes into spill runs on scratch, the merge orders rows, and one segment attach seals them. The re-encode holds no more than 64 MiB of decoded rows in memory at once. The portable attach functions take the spill budget as a new argument.
- BREAKING CHANGE: `attach_tx_lookup_artifact`, `attach_script_history_artifact`, and `attach_compact_filter_artifact` take a `&SpillBudget` argument; the `TxIndexWriter` attach methods for `TxLookup` and `ScriptHistory` take streamed run families instead of `ImportedSegment`.
- BREAKING CHANGE: `MempoolGateway::remove_for_block`, `settle_block_facts`, `expire`, `clear` and `evict_below_fee_rate` return `Result` carrying `MempoolError::DeliveryQueueFull` when a reentrant observer callback commits past the bounded delivery queue; callers propagate the error.
- Coins live in the engine `coins` keyspace. Windows and blocks commit their coin replacements in the same atomic batch as the durable head, undo rows and body index. The resident `UtxoSet` is the snapshot reader only.
- Epoch 4 datadir format. The `3 -> 4` step of `bitcoin-rs-storage-convert` loads the coin image of the newest checkpoint into the engine, replays the suffix to the durable head, and carries the epoch-3 `assumeutxo-historical-checkpoints` generations with their engine coins. Epoch-4 coin records use the Core-compressed txout value framing.
- The chainstate journal and its replay are removed, and so is the `utxo-v4.dat` checkpoint coin image as an authority. New checkpoints carry an engine image; `chainstate-checkpoints/` generations from epoch 3 are not copied into the epoch-4 datadir. The `[chainstate_journal]` config table and `BITCOIN_RS_CHAINSTATE_JOURNAL*` variables are removed.
- BREAKING CHANGE: the [chainstate_journal] table and BITCOIN_RS_CHAINSTATE_JOURNAL* variables are removed; a config that sets them fails startup as an unknown key.
- The `3 -> 4` step carries the epoch-3 full-revalidation marker (`chainstate-journal/full-revalidation`) to the epoch-4 datadir root, so a datadir marked for full revalidation still revalidates from cold after conversion.
- Derived index writes (`crates/projection/src/index/block.rs`, `write.rs`, `rows.rs`). The gap fallback parses each block body once, where it parsed twice before; the committed-facts path parses nothing. Legacy `TxConfirmed`, `Funding`, `Spending`, and compact-filter key rows are no longer written; transaction, script-history, and filter data live in the segment tail. Index format marker is 9: every per-block tail log record now carries the block hash anchor, so existing derived indexes rebuild on start.
- BREAKING CHANGE: the index format marker moves to 9. `IndexWriter::open` refuses an index at an older marker, then startup resets the index and rebuilds it.
- Batch byte limit (`crates/projection/src/index/prepared.rs`, `tail_writes.rs`, `rows.rs`, `write.rs`). A prepared batch's planned bytes now bound every index write its commit makes: they count the segment-tail undo log (`tail_log` family on `index.family_planned_write_bytes`), every spend row the tail can emit, and the per-commit watermark, revision, generation-descriptor, and consumer-cursor writes. The cursor is charged at its worst case, a full `CURSOR_BYTE_LEN` value, whatever the caller sets. Batches admitted under the old figure can carry more bytes than their limit; the same limit now admits fewer blocks per batch.
- Verified snapshot state for AssumeUTXO import (`crates/storage/src/utxo/core_snapshot.rs`, `crates/execution/src/assumeutxo.rs`, `crates/node/src/snapshot.rs`). `read_verified` seals the decoded portable set with its base hash, height, commitment and coin statistics, so portable activation performs no second commitment pass or statistics scan. Caller digests and snapshot trailers still establish no trust. Recorded compatibility boundary: files repeating txid groups are refused (`TransactionOrder`, RPC `-22`); Core 31.1 accepts such a file. No performance gain is claimed.
- The native v4 UTXO snapshot bootstrap path is removed (`Node::activate_assumeutxo_snapshot_file`, `NodeState::activate_assumeutxo_snapshot_file`, `SnapshotControl::import_native`, `AssumeUtxoManager::activate_native_snapshot`). Snapshot activation accepts Core portable v2 via `loadtxoutset` and manifest bundles via `Node::import_manifest`.
- BREAKING CHANGE: `Node::activate_assumeutxo_snapshot_file` is removed; embedders activate snapshots via `Node::import_manifest` (Core v2); native v4 snapshot files are no longer accepted as bootstrap input.
- Snapshot activation publishes a checkpoint at the snapshot base before the durable-head commit, and restart resumes from that checkpoint. The `assumeutxo/<base>/coins.dat` and `headers.dat` archive, its writer and reader (`write_coins_archive`, `write_headers`, `load_verified`), and the reservation probe are removed. Activation scans the installed engine coins and refuses a `hash_serialized` that differs from the pinned commitment.
- BREAKING CHANGE: the snapshot archive is gone and older datadirs need the converter. Epoch 5 datadir format: the current binary refuses an epoch 4 datadir, and restart requires the snapshot-base checkpoint. Convert directly with the `4 -> 6` step of `bitcoin-rs-storage-convert`, which verifies a valid archive (`headers.dat` linkage and proof of work, `coins.dat` hash against the compiled pinned value) and publishes the checkpoint into the new datadir without copying the archive. A datadir with a compatible checkpoint converts without republication, and an archive that fails verification refuses conversion with no marker written.
- `loadtxoutset` RPC always decodes the input as a Core portable v2 snapshot, independent of the filename; a `.json` suffix no longer routes a real Core file into the manifest decoder, and manifest bundles keep activating only through `Node::import_manifest`.
- Epoch 6 datadir format (`crates/storage/src/utxo/undo_codec.rs`, `tools/storage-convert`). An undo record holds only the coins that its block spends (`UNDO_FORMAT_VERSION = 2`), and the node derives the created outputs from the block bytes on disconnect. The `5 -> 6` step of `bitcoin-rs-storage-convert` recodes each version 1 undo row. Epoch 3 and epoch 4 sources chain their steps with that recode and write marker `6`.
- BREAKING CHANGE: a datadir at schema 5 or older is refused until `bitcoin-rs-storage-convert` writes it to schema 6.
- `UtxoReader::get`, `get_entry` and `has_live_outputs_for_txid` return `UtxoError` when the coin store cannot read or decode a coin row, and no longer report that coin as absent. `gettxout` and `gettxoutproof` answer Core `-32603`, `/rest/getutxos` answers HTTP 500, compressed-transaction decompression answers `coin set could not be read; retry` while compression reports the prevout as unreadable in its warnings, `generateblock` with raw transactions fails, and the mempool admission view returns no snapshot. Each of these previously answered as if the coin did not exist.
