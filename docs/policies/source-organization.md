# Source and test organization
Placement and naming defaults live here; [architecture](../contracts/architecture.md) owns dependency/state boundaries and [test-evidence](../contracts/test-evidence.md) owns which guarantees need independent proof: a directory change alters neither. Choose the existing owner and the behavior being changed before choosing a file; keep one authority per invariant, mutation, and durable format; a file split creates no new owner. Defaults guide new and reorganized code only.
New module: named responsibility, protocol, or algorithm in the existing crate; flat tree while readable. Split: entrypoint stays `owner.rs`, private children in `owner/part.rs` via ordinary module declarations (no facade or state). Name by current responsibility/behavior; seam over line limits, shards, tasks, or issue numbers; keep useful regression provenance in a concise test comment; logical paths follow physical paths (`owner/part.rs`, not root-prefixed `#[path]`); platform selection and shared-fixture imports explicit. Expose the narrowest visibility required; never add re-exports, wrappers, crates, or test-only production APIs for organization. Large files invite responsibility inspection, not automatic splits; dense algorithms and small crates need no uniform directory depth.
Owner-local tests MUST use an inline test module in the owner source file. Keep their module names, configuration conditions, and visibility. Crate-consumer tests and independent oracle tests MUST use the crate-root `tests.rs` file. Register that file as the `suite` integration target. These placement rules govern the packages under `crates/`; `bin/bitcoin-rs`, `e2e`, and `tools/*` keep their registered `tests/suite.rs` process harnesses. Test-only source directories under `crates/` are not permitted. File length alone does not justify a separate test module file.
Keep a separate crate-root test executable only when a process, platform, allocator, global counter, or artifact boundary requires it. Preserve each target name and its Cargo configuration. Daemon lifecycle, restart, and cross-process tests keep their existing process harness. Socket reads and store reopens alone do not require a separate target.
Inline test helpers in their using test module. A helper shared by independent test executables can use one crate-root helper file. Do not copy the helper into each executable. Preserve one owner for each fixture and error domain. Reference data belongs under `testdata/<owner>/`, outside `crates/`. Preserve external vectors, provenance, and fixture bytes when paths change. Do not reach into another package's private test source tree or add a shared framework only for path uniformity. Overlapping inputs require a different oracle or failure boundary.
An exception needs a concrete current reason (process, platform, allocator, global counter, artifact, or required compilation boundary, or independent oracle custody), explained in the PR with a nearby comment only if future maintainers need it. Existing placement never justifies a new exception. No waiver registry, approval step, or directory-shape test.
Reorganizations preserve intended visibility, test registration, cfg/feature/backend/platform selection, independent references, and failure coverage; remove superseded paths/helpers with their replacements; run the smallest meaningful checks for affected boundaries; review tests by retained guarantee, not counts; update guidance at the single owning rule, never by crate-local copy.
