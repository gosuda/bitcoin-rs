# Source and test organization
Placement and naming defaults live here; [architecture](../contracts/architecture.md) owns dependency/state boundaries and [test-evidence](../contracts/test-evidence.md) owns which guarantees need independent proof: a directory change alters neither. Choose the existing owner and the behavior being changed before choosing a file; keep one authority per invariant, mutation, and durable format; a file split creates no new owner. Defaults guide new and reorganized code only.
New module: named responsibility, protocol, or algorithm in the existing crate; flat tree while readable. Split: entrypoint stays `owner.rs`, private children in `owner/part.rs` via ordinary module declarations (no facade or state). Name by current responsibility/behavior; seam over line limits, shards, tasks, or issue numbers; keep useful regression provenance in a concise test comment; logical paths follow physical paths (`owner/part.rs`, not root-prefixed `#[path]`); platform selection and shared-fixture imports explicit. Expose the narrowest visibility required; never add re-exports, wrappers, crates, or test-only production APIs for organization. Large files invite responsibility inspection, not automatic splits; dense algorithms and small crates need no uniform directory depth.
Owner-local behavior (including required private access): short inline `#[cfg(test)] mod tests`, larger suites in `src/owner/tests.rs` (owner-declared `#[cfg(test)]`), further splits behavioral under `src/owner/tests/`; crate-root behavior in `src/tests.rs`. Crate-consumer boundary or independent oracle: `tests/<behavior>.rs` with helpers in `tests/support/`. Daemon lifecycle, restart, or cross-process/reference behavior: the existing process harness at the owning package/e2e boundary, preserving real process/persistence evidence. Socket reads and store reopens alone do not require integration targets; `tests/unit/` files pulled via `#[path]` remain unit tests; keep classifications, dispatcher policy, transport behavior, and state transitions with their proof owners. Overlapping inputs are justified when the oracle or failure boundary differs.
Fixtures belong to the smallest using scope: local with the suite; intra-crate via `tests/support/`; cross-crate via an existing domain fixture or harness owner with its feature/dependency boundary. Never copy fixtures, reach into another package's private test tree, or build a shared framework for path uniformity; the smallest shared boundary is justified by actual consumers.
An exception needs a concrete current reason (platform selection, independent oracle custody, required compilation boundary), explained in the PR with a nearby comment only if future maintainers need it. Existing placement never justifies a new exception. No waiver registry, approval step, or directory-shape test.
Reorganizations preserve intended visibility, test registration, cfg/feature/backend/platform selection, independent references, and failure coverage; remove superseded paths/helpers with their replacements; run the smallest meaningful checks for affected boundaries; review tests by retained guarantee, not counts; update guidance at the single owning rule, never by crate-local copy.
