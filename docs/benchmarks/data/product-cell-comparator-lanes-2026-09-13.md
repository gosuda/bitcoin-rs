The within-run 7-arm spread frequently exceeds the 5% product-stability band. That is expected. An arm is a 0.11-0.13 s fixture process spawn. The wall therefore measures scheduler placement, child subreaper sweeps and Python GC/startup jitter on a shared 80-CPU host. It does not measure comparator work. This spread is not the `HPA-03` noise floor, which is `max(B1..B7) - min(B1..B7)` over seven valid bitcoin-rs walls of a real corpus cell. It is also not a product candidate/control comparison. Both arms of each fixture pair are the same program. p2p writes `core-node.py` and `candidate-node.py` from one `_node_source` in `comp_lanes.py`. Offline calls the same fixture program for both roles. A fixture ratio near 1.0 is therefore a plumbing check, not a product result (`HPA-09`). The `HPA-13` stability predicate (each arm within 5% of its own median, improvement exceeding host noise) remains unexercised. No candidate/control product pair was measured.
## Why the live product-cell arms did not run
The #34 offline lane needs bitcoin-rs to apply a Core-framed archive at `assume_valid_height 0` to the manifest stop height. It must then persist bodies, undo and the production checkpoint, and exit. The #41 lane needs a bitcoin-rs node whose committed UTXO set at height 150,000 answers `gettxoutsetinfo` with the CORP-05 oracle values. The #35 P2P lane needs a live loopback IBD between real Core 31.1 and bitcoin-rs nodes. None of these can start from this tree. `bin/bitcoin-rs/src/cli.rs` exposes no corpus, manifest, archive, blocks-dir or stop-at-height flag, and offers only `run` and `measure_storage`. `crates/node/src/import.rs` is an explicit skeleton, and its `import_block` is not wired to any archive source or CLI path. Both paths were present at this record's date: `import.rs` was deleted 2026-09-17 in `c64f82be4`, and `cli.rs` was consolidated 2026-10-03 in `f9c06fb4c`. `gettxoutsetinfo`, in `crates/rpc/src/handlers/chain.rs`, answers the current in-memory UTXO view but refuses specific-height queries. No shipped offline path places the node at the frozen tip with certified state. The P2P lane's product form is not shipped: `tools/benchmark-campaign/p2p_loopback.py` is a scripted-peer fixture harness, and the historic `mainnet_prefix_replay` tool was retired. A live loopback IBD has no stop-at-height, and the comparator requires RPC-ready within `ARM_READY_TIMEOUT_NS = 10 s` on pre-constructed state (`tools/benchmark-campaign/muhash_rpc.py`). The missing ingest path cannot supply that state.
No Core-vs-bitcoin-rs campaign ran as a result. The candidate arm cannot be placed at the frozen tip. Running the Core side alone would produce one-arm, no-counterpart evidence that the contract refuses (`HPA-08`). This is a capability and harness blocker, not a custody blocker (#34 and #35). It is also a state-construction budget blocker, not an RPC absence. The RPC is implemented (#41), and the state is constructible only via a long IBD with no stop-at-height or shipped harness.
