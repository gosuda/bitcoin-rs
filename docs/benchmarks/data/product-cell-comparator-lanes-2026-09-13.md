The within-run 7-arm spread frequently exceeds the 5% product-stability band. That is expected. An arm is a 0.11-0.13 s fixture process spawn. The wall therefore measures scheduler placement, child subreaper sweeps and Python GC/startup jitter on a shared 80-CPU host. It does not measure comparator work. This spread is not the `HPA-03` noise floor, which is `max(B1..B7) - min(B1..B7)` over seven valid bitcoin-rs walls of a real corpus cell. It is also not a product candidate/control comparison. Both arms of each fixture pair are the same program. p2p writes `core-node.py` and `candidate-node.py` from one `_node_source` in `comp_lanes.py`. Offline calls the same fixture program for both roles. A fixture ratio near 1.0 is therefore a plumbing check, not a product result (`HPA-09`). The `HPA-13` stability predicate (each arm within 5% of its own median, improvement exceeding host noise) remains unexercised. No candidate/control product pair was measured.
## Why the live product-cell arms did not run
The #34 offline lane needs bitcoin-rs to apply a Core-framed archive at `assume_valid_height 0` to the manifest stop height. It must then persist bodies, undo and the production checkpoint, and exit. The #41 lane needs a bitcoin-rs node whose committed UTXO set at height 150,000 answers `gettxoutsetinfo` with the CORP-05 oracle values. The #35 P2P lane needs a live loopback IBD between real Core 31.1 and bitcoin-rs nodes. The offline #34 need has a shipped path now: `--corpus`, `--manifest` and `--state` (given together) route to `run_offline_import` in `crates/node/src/offline_import.rs`, which replays a core-framed or corpus-manifest archive under full validation, publishes the production checkpoint, and writes the certified state to `--state`. At this record's date `bin/bitcoin-rs/src/cli.rs` exposed no corpus, manifest, archive, blocks-dir or stop-at-height flag and offered only `run` and `measure_storage`, and `crates/node/src/import.rs` was an unwired skeleton. `import.rs` was deleted 2026-09-17 in `c64f82be4`, and `cli.rs` was consolidated 2026-10-03 in `f9c06fb4c`. `gettxoutsetinfo`, in `crates/rpc/src/handlers/chain.rs`, answers the current in-memory UTXO view but refuses specific-height queries, so the #41 height-150,000 oracle comparison stays blocked. The P2P lane's product form is not shipped: `tools/benchmark-campaign/p2p_loopback.py` is a scripted-peer fixture harness, and the historic `mainnet_prefix_replay` tool was retired. A live loopback IBD still has no stop-at-height flag, and the comparator requires RPC-ready within `ARM_READY_TIMEOUT_NS = 10 s` on pre-constructed state (`tools/benchmark-campaign/muhash_rpc.py`).
No Core-vs-bitcoin-rs campaign ran as a result. At the record date the candidate arm could not be placed at the frozen tip, and that block was capability and harness, not custody (#34 and #35). Custody split 2026-11-01: the cmodern corpus is missing, so every cmodern cell is blocked on the missing archive and manifest; C150 custody is staged, the offline state construction ships, and no comparator campaign has run against it. The live-IBD arm still has no stop-at-height flag. The RPC is implemented (#41).
