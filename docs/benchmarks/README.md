# Benchmark evidence rules
## Required identities per sample

Every sample records six identities. The first is the artifact SHA-256 plus the source commit. The second is the resolved `NodeConfig`, feature set, allocator and validation mode. The third is the corpus digest, height range, stop height and stop hash. The fourth is the backend, batch mode (`write`, `write_deferred`, `write_durable`), flush and sync posture. The fifth is the toolchain (`rustc 1.99.0`, edition 2024, profile, features). The sixth is the hardware (CPU model, pinned cores, memory, storage device, OS kernel). The evidence collector (`crates/node/benches/evidence.rs`, `tools/benchmark-campaign/evidence.py`) rejects a sample that lacks any of them. A rejected sample is not evidence.
## Acceptance rule
To promote a candidate over its control, the median gain must be at least 1.05x over at least three alternating candidate/control runs. Each arm must stay within 5% of its own median, and the improvement must exceed the observed host noise. Non-target cells guard at no more than 3% median and 5% p99 regression. They use repeated runs and report uncertainty. Average-only reporting never passes. Report p50, p95, p99 and max with the sample count. Never sum nested or concurrent intervals. Parallel worker walls and inclusive stage histograms sit beside the process wall, and no one adds them to it. Retain raw samples beside every summary. A Criterion adaptive elapsed total is not a median source. If a binary, corpus, hardware target or digest is missing, mark the cell `BLOCKED` and name the missing identity. `BLOCKED` is never a pass and never a skip.
## Status vocabulary
A page marked `planned_not_executed` has run no end-state cell. Every value in its end-state tables is a required contract value, not a measurement. Its `Prior candidate evidence` section is historical and proves no end-state cell.
## Non-evidence numbers
`Observed once, not evidence` marks a number kept for context. It has no six-identity sample. It supports no acceptance verdict and no promotion. Remove it, or replace it with a gated cell, when the evidence exists.
## Comparator custody
The shared evidence owner is `tools/benchmark-campaign/evidence.py`. The comparator controllers `muhash_rpc.py`, `p2p_loopback.py` and `offline_full_validation.py`, and the operator identity capture, import it. It guarantees these properties. A comparator MUST NOT restate or replace them.
- Canonical bytes (`canonical_bytes`, `canonical_sha256`): one ASCII encoding per value. Object keys are sorted, separators are `,` and `:`, and strings are ASCII-escaped. A non-finite float or `Decimal` is refused. A recursion failure is refused. One value therefore has one digest.
- Percentiles (`nearest_rank`, `summarize`): the sorted sample at zero-based index `ceil(p * n) - 1`. `summarize` reports the sample count, `p50`, `p95`, `p99` and `max`. An empty sample and a percentile outside `(0, 1]` are refused. No mean is computed.
- File hash (`hash_regular_file`): the SHA-256 of one regular file. The path is opened with `O_NOFOLLOW`. A symlink, another file type or an open failure is refused.
- Pinned copy (`copy_pinned`): a copy whose bytes match a pinned SHA-256. The source is opened with `O_NOFOLLOW` and must be a regular file. `O_EXCL` refuses an existing destination. The digest is updated as the bytes are copied. The copy receives the requested mode (default `0o500`) and an fsync. The destination is re-opened with `O_NOFOLLOW` and hashed again. A digest mismatch or an I/O failure unlinks the copy. A digest mismatch raises `ContractError`. The owner does not retry.
- Process identity (`process_start_time`): the start time of one PID, read from `/proc/<pid>/stat` after the command name. A read failure, a short stat or a non-numeric field is refused. A controller that records this value binds an observation to one process lifetime.
- Publication (`publish_result`): one atomic result document on Linux. The document MUST NOT nest deeper than `MAX_JSON_DEPTH` (32). Publication writes `canonical_bytes(result)` plus one newline. The output MUST name a file inside an existing directory. The parent MUST be owned by the effective user and MUST NOT have a group or other write bit. Each ancestor is opened with `O_NOFOLLOW` from the previous descriptor. An ancestor that an untrusted user could rename through is refused, unless it is a root-owned sticky directory with an effective-user-owned, non-writable child. Bytes go to an unnamed `O_TMPFILE` inode and are fsynced. The parent identity is checked again before the link. The commit point is a successful `linkat(AT_EMPTY_PATH)`, then an inode check, then a directory fsync. A crash before the link leaves the destination unchanged. A retry after the link gets `EEXIST`; the published bytes are the committed document and MUST NOT be overwritten. A failure after the link removes only the inode that this process linked, after a no-follow device and inode check. An uncatchable interruption after the link can leave a complete record whose directory fsync did not run. The owner does not retry; the caller owns the retry policy and chooses a new output path.
