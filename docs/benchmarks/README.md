# Benchmark evidence rules
## Required identities per sample

Every sample records six identities: artifact SHA-256 plus source commit; resolved `NodeConfig`, feature set, allocator, validation mode; corpus digest, height range, stop height and stop hash; backend, batch mode (`write`, `write_deferred`, `write_durable`), flush and sync posture; toolchain (`rustc 1.99.0`, edition 2024, profile, features); hardware (CPU model, pinned cores, memory, storage device, OS kernel). The T02 collector rejects a sample lacking any of them; a rejected sample is not evidence.
## Acceptance rule
Promotion of a candidate over its control requires a median gain of at least 1.05x over at least three alternating candidate/control runs, each arm within 5% of its own median, the improvement exceeding observed host noise. Non-target cells guard at no more than 3% median and 5% p99 regression with repeated runs and reported uncertainty; average-only reporting never passes. Report p50, p95, p99 and max with the sample count; never sum nested or concurrent intervals (parallel worker walls and inclusive stage histograms sit beside the process wall, never added to it); retain raw samples beside every summary (a Criterion adaptive elapsed total is not a median source). A missing binary, corpus, hardware target or digest marks the cell `BLOCKED` with the missing identity named; `BLOCKED` is never a pass and never a skip.
## Status vocabulary
A page marked `planned_not_executed` has run no end-state cell: every value in its end-state tables is a required contract value, not a measurement, and its `Prior candidate evidence` section is historical and proves no end-state cell.
