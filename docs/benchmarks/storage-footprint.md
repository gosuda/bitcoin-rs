# Storage footprint benchmark evidence
Measure with the offline Linux tool under [the measurement boundary](../contracts/storage-footprint.md): `cargo run --locked -p bitcoin-rs-storage-footprint -- /path/to/data-dir > /path/outside-data-dir/footprint.json` (output stays outside the measured directory so redirection never creates or truncates a file inside the snapshot). Record the revision/build, backend, network, index configuration, pinned stop height/hash, and workload beside the output; compare matched runs. Filesystem apparent bytes are not logical serialized data-model bytes; a final allocation snapshot alone measures no peak and certifies no mainnet storage budget. Capture peak usage independently, never silently prune, discard witness data, or hide temporary files to meet a target. Current priorities: actual IBD time, final database size, peak disk use, compaction amplification, restart/reorg behavior, backend comparisons.

2026-09-04 synthetic corpus, 129,570,000 logical bytes (`Spending 12+8`): filesystem-length totals 86,728,585 bytes (fjall) and 269,488,128 bytes (redb), historical synthetic numbers, not mainnet evidence and not allocated-byte measurements from the current tool.

Full-tip/peak results remain unmeasured here; there is no in-tree footprint verdict machine.
