# CHECKSIG census experiment

Answers wayfinder ticket **Task: CHECKSIG census and per-check floor comparison over 0-150k**.

Measures the per-CHECKSIG-attempt cost floor in `CPubKey::Verify` from
libbitcoinkernel-sys 0.3.0 (via bitcoinkernel 0.2.1, embedding Bitcoin Core
31.99.0 development sources) and compares it against the per-input
script-verification cost in bitcoin-rs. If the residual `R = X - F` is large
enough, script verification has headroom worth optimizing; if `R` is near zero
or negative, CHECKSIG attempts are the floor and no script-path optimization
can help. The comparator is native `CPubKey::Verify` from that development
tree, not an irreducible cryptographic floor; the residual is a ceiling over
non-native per-check work, not a guaranteed removable gain.

## Setup

Before building, create a fresh instrumented `libbitcoinkernel-sys` copy.
This step is **not idempotent**: it refuses to overwrite an existing tree so
the patch is never applied twice to the same copy.

```bash

EXP=$REPO/tools/checksig-census

cd "$REPO"
cargo fetch --locked
PRISTINE=$(python3 -c 'import os; from pathlib import Path; root = Path(os.environ.get("CARGO_HOME", Path.home() / ".cargo")) / "registry/src"; matches = sorted(root.glob("*/libbitcoinkernel-sys-0.3.0")); assert len(matches) == 1, matches; print(matches[0])')

if [ -e "$EXP/libbitcoinkernel-sys-0.3.0" ]; then
  echo "instrumented copy already exists; remove $EXP/libbitcoinkernel-sys-0.3.0 to rerun setup"
  exit 1

cp -a "$PRISTINE" "$EXP/libbitcoinkernel-sys-0.3.0"
patch --fuzz=0 -p1 -d "$EXP/libbitcoinkernel-sys-0.3.0" < "$EXP/instrumentation.diff"
```

## Run sequence

### Find or recover the Cmodern candidate height

Use `find-cmodern-height` to stop the diagnostic replay at the first height where all 11 special context counters are nonzero:

```bash
python3 analyze.py find-cmodern-height \
  --binary "$EXP/target/release/examples/mainnet_prefix_replay" \
  --rest-url 127.0.0.1:18443 \
  --stop-height 961741 \
  --work-dir "$EXP/out/cmodern-diagnostic" \
  --output "$EXP/out/cmodern-candidate.json"
```

The candidate is diagnostic evidence, not a certifying corpus. A terminal checkpoint binds the selected height and hash to the committed stream row counts and byte endpoints. The child can finish those writes before its process teardown completes. Schema `cmodern-candidate-diagnostic-v2` therefore records `child_exit_status`, `child_teardown`, and `salvaged_from` separately instead of reporting a forced kill as a clean exit.

If the child wrote the terminal checkpoint but did not exit before the controller deadline, preserve the failed work directory and recover into new paths:

```bash
python3 analyze.py salvage-cmodern-height \
  --source-dir "$EXP/out/cmodern-diagnostic" \
  --recovery-dir "$EXP/out/cmodern-recovery" \
  --rest-url 127.0.0.1:18443 \
  --stop-height 961741 \
  --data-dir "$EXP/out/cmodern-diagnostic/state" \
  --storage-backend fjall \
  --output "$EXP/out/cmodern-candidate.json"
```

Salvage opens every source artifact once and keeps those descriptors open through publication. It validates each checkpoint-committed slice and hashes the source streams during that same pass. It reflink-clones or copies the files into the new recovery directory, truncates each stream at its committed endpoint, and resets only the recovery sidecar header. `source_full_file_custody` records a direct full-file SHA-256 and `clone_provenance` (`EXACT_FULL_FILE` or `DIFFERS_FROM_SOURCE`) for every source. Stream entries also record the committed-prefix SHA-256. Final validation hashes the recovery streams and requires those hashes to equal the source committed-prefix hashes. The source paths, bytes, and metadata must remain unchanged until the candidate is published.

`--rest-url` comes from the original controller command. The child replay JSON does not contain that value, so salvaged candidates label it `operator_supplied_original_argv`. `--data-dir` must match the exact string in `replay_diagnostic.json`. Do not resolve or rewrite it.

### Run C — bare-secp per-attempt timing (native mode 0)

```bash
REPO=/home/alpha/exp/bitcoin-rs
EXP=$REPO/tools/checksig-census
BARE=$EXP/target/release/checksig-bare-secp

for RUN in 1 2 3; do
  taskset -c 0-31 "$BARE" \
    --records "$EXP/out/kspike1.records.sorted.bin" \
    --output "$EXP/out/bare-secp-${RUN}.json"
done
```

Each run produces a top-level `native_mode0` object with per-round timing.
The analyzer sets `Y` to the median of the three per-run medians, where each
per-run median uses `round_ns / inputs_per_round`. The verdict command rejects
any run count other than exactly three for the bare comparator and width-1
spike inputs. Each file also contains:

- `inv_8` (native correctness: `mismatches == 0`, `ok_count == expected_true_count`,
  `expected_true_count` equal to the capture count, `ok_equals_count_outcome_1 == true`,
  and `passed == true`);
- `inv_15` (exactly the 24 named post-timing counters, each integer zero,
  plus `all_counters_zero == true` and `passed == true`);
- `rust_secp_diagnostic` — a 2-record parser incompatibility between Rust
  secp256k1 0.31.1/libsecp 0.6.0 and the native tree (Bitcoin Core 31.99.0
  development sources) that causes 2 expected-valid preparse failures. This
  is a **diagnostic** incompatibility and does NOT invalidate the native
  authoritative arm. INV-8 gates only on native correctness; the Rust
  diagnostic is reported but not gated.
- `schema` and `records_total`/`records_rejected_pre_secp` for cross-checks.

INV-14 is supplied through `--integrity`. The analyzer validates all four
source hashes, recomputes both equality predicates, and rejects contradictory
summary booleans.

#### `native_mode0` JSON schema

The bare JSON must contain a top-level `native_mode0` object with these
exact fields (no defaults — missing fields cause a loud failure):

| Field | Type | Constraint |
|-------|------|------------|
| `inputs_per_round` | int | positive |
| `rounds` | int | positive |
| `attempts_total` | int | `== inputs_per_round * rounds` |
| `round_ns` | list[int] | length == `rounds`, each positive |
| `median_ns_per_attempt` | float | agrees with recomputed median within 1e-6 rel tol |
| `min_ns_per_attempt` | float | agrees with recomputed min within 1e-6 rel tol |
| `max_ns_per_attempt` | float | agrees with recomputed max within 1e-6 rel tol |
| `mismatches` | int | non-negative |
| `first_mismatch` | object\|null | — |
| `ok_count` | int | non-negative |

Per-attempt round cost is `round_ns[i] / inputs_per_round` — never divided
by `attempts_total` for a single round. The analyzer independently recomputes
per-round costs and requires the reported median/min/max to agree within
floating tolerance. The **median** (not mean) of per-round costs is the
authoritative `Y`.

#### INV-8 (native correctness)

The analyzer expects `inv_8` with these exact fields:
`passed`, `mismatches`, `ok_count`, `expected_true_count`,
`ok_equals_count_outcome_1`. It recomputes `mismatches == 0`,
`ok_count == expected_true_count`, `expected_true_count` equals the capture
count, `ok_equals_count_outcome_1 == true`, and the emitted `passed` value is true.
Rust secp256k1 preparse failures remain diagnostic and do not gate INV-8.

### Generate integrity JSON (INV-14 source-identity proof)

INV-14 proves the patched `libbitcoinkernel-sys` builds from the same
`bitcoin/src/pubkey.cpp` and `bitcoin/src/secp256k1` tree as the pristine
cargo-registry source, so the native timing reflects unmodified
`CPubKey::Verify` logic from Bitcoin Core 31.99.0 development sources.
Object-byte identity is deliberately not required
because RelWithDebInfo embeds absolute source paths in debug info; the build
has no LTO or IPO.

```bash
REPO=/home/alpha/exp/bitcoin-rs
EXP=$REPO/tools/checksig-census
PRISTINE=/home/alpha/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/libbitcoinkernel-sys-0.3.0
PATCHED=$EXP/libbitcoinkernel-sys-0.3.0

mkdir -p "$EXP/out"

# Hash pristine and patched pubkey.cpp
PRISTINE_PUBKEY=$(sha256sum "$PRISTINE/bitcoin/src/pubkey.cpp" | cut -d' ' -f1)
PATCHED_PUBKEY=$(sha256sum "$PATCHED/bitcoin/src/pubkey.cpp" | cut -d' ' -f1)

# Deterministic sorted file-hash manifest for bitcoin/src/secp256k1
secp_manifest() {
  local base="$1/bitcoin/src/secp256k1"
  find "$base" -type f | sort | while read -r f; do
    printf '%s  %s\n' "$(sha256sum "$f" | cut -d' ' -f1)" "${f#"$base/"}"
  done
}
PRISTINE_SECP=$(secp_manifest "$PRISTINE" | sha256sum | cut -d' ' -f1)
PATCHED_SECP=$(secp_manifest "$PATCHED" | sha256sum | cut -d' ' -f1)
SECP_FILE_COUNT=$(find "$PRISTINE/bitcoin/src/secp256k1" -type f | wc -l)

cat > "$EXP/out/integrity.json" <<EOF
{
  "schema": "integrity-v1",
  "pubkey_source_identical": $([ "$PRISTINE_PUBKEY" = "$PATCHED_PUBKEY" ] && echo true || echo false),
  "secp_tree_identical": $([ "$PRISTINE_SECP" = "$PATCHED_SECP" ] && echo true || echo false),
  "pristine_source_hash": "$PRISTINE_PUBKEY",
  "patched_source_hash": "$PATCHED_PUBKEY",
  "pristine_secp_tree_hash": "$PRISTINE_SECP",
  "patched_secp_tree_hash": "$PATCHED_SECP",
  "secp_file_count": $SECP_FILE_COUNT,
  "note": "Build has no LTO or IPO; source paths are embedded in RelWithDebInfo objects, so object-byte identity is not required."
}
EOF
```

## Decision arithmetic

| Symbol | Meaning | Source |
|--------|---------|--------|
| `X` | µs per input check at width 1 | Run D spike, median of width-1 `us_per_input` |
| `Y` | ns per native Core `CPubKey::Verify` attempt | Run C, median of per-round `round_ns / inputs_per_round` |
| `A` | `ecdsa_verify_calls` | Run B capture counters |
| `K` | `ffi_verify_entries` | Run B capture counters |
| `a` | attempts per check = `A / K` | derived |
| `F` | floor µs per check = `a × Y / 1000` | derived |
| `R` | residual µs per check = `X - F` | derived |
| `r` | residual fraction = `R / X` | derived |
| threshold | `0.05 × total_wall / script_wall` | recomputed from current replay |

**Verdict**:
- `r ≥ threshold` → **OPEN** (script verification has headroom)
- `0 ≤ r < threshold` → **CLOSED** (no stage-significant residual at this threshold)
- `R < -noise` → **INVALID** (capture or comparator is wrong)
- INV-8/14/15 fail → **INVALID** (bare arm contaminated)

Standing threshold from the current 69.6s replay and 12.55s script stage: 27.73%.
The residual is a ceiling over non-native per-check work, not a guaranteed
removable gain.

## Binary formats

All integers are host little-endian (x86_64 only). Files start with 8-byte
magic + u64 count.

**Records** (magic `BRSREC1\0`, 224 bytes each):
spend_txid[32], input_index u32, op_seq u32, op_kind u8, sig_version u8,
outcome u8 (0=false, 1=true, 2=pre-verification reject), der_len u8,
pubkey_len u8, sighash_type u8, reject_reason u8, pad u8, sighash[32],
der_sig[72], pubkey[65], pad[7]. Reject reasons are: 0 none; 1 invalid
ECDSA pubkey; 2 empty ECDSA signature; 3 missing ECDSA transaction data;
4 invalid Schnorr signature size; 5 explicit-default Schnorr hash type;
6 missing Schnorr transaction data; 7 Schnorr sighash failure; 8 empty
Tapscript Schnorr signature skipped before `CheckSchnorrSignature`.

The on-disk 224-byte layout is fixed: `pubkey_len` preserves the low 8 bits of
the source public-key stack element. A semantic reader may accept `pubkey_len >
65` only for the exact native reason-1 pre-verification reject shape: `outcome
== 2`, `reject_reason == 1`, `op_kind` in 1..4, `sig_version` in {0, 1},
`der_len == 0`, `sighash_type == 0`, and all `sighash`, `der_sig`, `pubkey`,
and padding bytes zero. Every other over-capacity record keeps the existing
`pubkey_len ... exceeds 65` rejection.

**Journal** (magic `BRSJRN1\0`, 56 bytes each):
spend_txid[32], input_index u32, checksig_ops u32, checkmultisig_ops u32,
ecdsa_verify_calls u32, ecdsa_verify_ok u32, verdict u8, pad[3].

**Contexts** (magic `BRSCTX1\0`, variable-length rows):
row_len u32; spend_txid_le[32]; input_index u32; verify_flags u32;
prevout_script_len u32; script_sig_len u32; witness_count u32;
exact prevout scriptPubKey bytes; exact scriptSig bytes;
for each witness item u32 item_len + exact item bytes.
`row_len` counts the bytes after the `row_len` field itself.

**Counters JSON**: schema=1, label, 24 named u64 counters, record_count,
journal_count, context_count.
